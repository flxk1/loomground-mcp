# Changelog

## Unreleased

* `privacy_scan` no longer returns an original. On main it returned the `ScanReport` itself, and `plain()` reflects a dataclass before it looks for `to_dict`, so `spans[].value`/`.context` — the verbatim email, IBAN or name — reached the envelope on all 16 `mode` × `redaction_mode` combinations, `redact` included. It now serialises through privacy-shield's `to_dict()`, and withholds `overlay` (as `overlay: null` with a named `overlay_withheld`) whenever a detected span's original may still be in it — its `value` still in the overlay, or a `value` that is empty, null or not the text at the span's offsets, since the local-model layer records a hint as `value` with `end = start + 10`, which let the rest of an address out under `redact`: under `detect_only` nothing redacts and under `block` the redactor may refuse (it does for an IBAN), and then the overlay is the untouched original while `egress_allowed` stays true — privacy-shield's source-class verdict, left as it is. A last check walks every string of the serialised payload and returns `unavailable` if any detected value survives, so a privacy-shield inside the range whose serialiser still carries originals is refused whole. The dev pin moves from the pre-release `111d630` — which reports 2.0.0 but predates the serialiser that omits originals — to `dc71ff0` (`v2.1.1`); the range is unchanged. `privacy_scan` takes `hash_salt`, forwarded only when given, so `redaction_mode="hash"` works and fails closed without one. The envelope test reads the whole envelope, not `overlay`, over every `mode` × {`redact`, `block`, `detect_only`, `pseudonymize`}; `hash` is covered by its own two tests, salted and unsalted. The residual check is by substring, so it errs towards withholding: a detected `Berg` withholds the overlay of a text that also says `Bergbau`. Carried from `mcp-drop-private-skill-records` (`d0320aa`, `0aaf456`, `863804d`, `a7c1f03`): the host converter splits `allowed-tools` on commas at paren depth zero and keeps a host grant such as `Bash(privacy-shield:*)` or `Read` out of `includeTools`, reporting it as a grant. The same split is now in the server: `tools/vendor_skills.py` splits `allowed-tools` at paren depth zero on commas or whitespace when it writes and when it checks the index, the parity test uses it, and the prompt header names host grants apart from served tools (`tools: privacy_scan; host grants: Bash(privacy-shield:*) Read`); every other skill's record is unchanged by it. That branch's re-vendoring of the catalogue, register and skills was not carried. Merged with the published line, which had moved every sibling pin onto the rebuilt repositories' commits (the earlier ones are gone from GitHub) and re-vendored the snapshot at loomground `67f45b8` with the seven governance-layer roles: those pins and that snapshot are taken, and pyproject keeps its ranges rather than the published line's direct git references, which named privacy-shield `v1.0.0` — out of range, on the old import root, and serialising originals. The applied runtimes are pinned at the GitHub commits of the releases the ranges admit: policy-compiler `policy-compiler-v0.3.0` (`d14e9a8`), evidence-emitter `v0.1.0` (`07af3e3`), privacy-shield `v2.1.1` (`dc71ff0`), a2a-compliance `v0.3.0` (`fd22399`). That takes a2a-compliance back from the published line's `v0.4.0`, which the `>=0.3,<0.4` range does not admit, and policy-compiler forward from its `v0.2.0`. The vendored privacy-shield skill moves from `111d630`, which the rebuild removed from GitHub, to `v2.1.1` (`dc71ff0`), the release the runtime pin installs, whose `allowed-tools` is `privacy_scan, Bash(privacy-shield:*), Read`. The vendored register still records the published line's pins until loomground regenerates it; 262 tests in CI's configuration.

* No build input from a working repository. CI fetched `skills_lint` from `flxk1/repo-standards` on every run — a published product taking a build input from the repository where the rules are still being drafted, which also breaks every consumer the day that repository turns private, because a default CI token cannot read another private repository. The linter is now vendored the way the skills are: `tools/vendored/skills_lint.py` and its `tools/undecidable.py` import, copied from `repo-standards` at `12dd6d3` (its `main`; the previously fetched `0a99ad8` is nine rounds old), recorded in `skills/vendored.json` under a new `tools` section with repository, commit, source directory, tree URL and a sha256 per file, so `tools/vendor_skills.py --check` detects a vendored copy that has drifted from the commit it claims — which the fetch never did for what it downloaded. A tool is vendored by name rather than wholesale, because this consumes one check out of a repository of them; the check holds `tools/vendored/` to exactly the recorded list. The workflow fetches nothing from `repo-standards`, the lint step is unconditional and asserts the verdict line as well as the exit code (the linter's own exit 2 means it linted nothing), and three tests prove the vendored copy still enforces the rules nothing else here enforces: description ≤ 1024, the allowed frontmatter keys, and that a description says when to use the skill. The newer linter changes no verdict on the vendored tree — still 26/26 — and its skip list now matches relative to the scan root, so the `work`-component workaround is gone and a test holds the property instead. New `tests/test_build_inputs.py` keeps the shape from returning: every repository the workflow fetches and every git-pinned requirement must be one the catalogue carries as published (32 of them, all pass), a vendored repository must not also be fetched, and `repo-standards` must appear in neither; 207 tests.

* The vendoring gate, hardened where it would not have caught things. `skills_lint` is handed a path relative to the vendored tree's parent, never an absolute one: it matches its skip list — which contains `work` — against every part of the path it is given, and a GitHub runner's workspace is `/home/runner/work/<repo>/<repo>`, where the absolute path made it skip every skill and exit 2 with nothing linted; the test asserts the `26/26 skills conform` line as well as the exit code, so a silent nothing-to-do cannot read as a pass. `--check` now walks the tree from the disk instead of from the manifest, so a directory carrying no SKILL.md (`skills/<repo>/<skill>/notes.md`, a stray `scripts/evil.py`, an editor's `SKILL.md~`) is a finding rather than a free ride into the wheel; it re-derives each `index.json` entry from the vendored SKILL.md and compares it whole, so a fabricated description fails; a referenced path that exists as a directory where the body names a file fails; and a vendored file that is empty fails. `exclude-package-data` keeps compiled byte-code out of the wheel, and the packaging test is now exact — `package-data` minus `exclude-package-data` must equal the manifest plus `index.json` and `vendored.json`, in both directions. A pin is per skill: a no-argument run honours a deliberately older per-skill commit instead of silently re-pinning it forward, and says so when one repository's skills diverge. `test_ci_has_every_pinned_source` fails by name under `CI` when any pinned source is absent, and the three guarded fetches are unguarded — both `e5a8970` fetches succeed today, and the comment claiming otherwise was false, so a lost fetch fails the job instead of turning two byte-parity tests into a silent skip. `test_every_dependency_this_repository_declares_has_an_edge` names the four applied skill runtimes the vendored register does not carry as edges (`AHEAD_OF_REGISTER`), so that gap cannot pass silently and any other dependency losing its edge fails; 167 tests.

* Skills vendored whole, by a tool, with a check: twelve SKILL.md bodies pointed at `scripts/` and `references/` files this repository did not carry, because the skills were hand-copied and package-data globbed `skills/*/*/SKILL.md` — the supporting files were dropped twice over, and nothing here would have said so. `tools/vendor_skills.py` now copies each `skills/<name>/` directory out of its repository at a pinned commit, records repository, commit, source directory, URL and every file's sha256 in `skills/vendored.json`, and is re-runnable; `--check` compares tree to manifest and applies `skills_lint`'s referenced-path rule, and `tests/test_skills_vendoring.py` runs the same check plus package-data coverage against the installed package, with no checkout and no network, so neither can skip. Package-data is `skills/*.json` and `skills/**/*` (setuptools >=62.3): the wheel goes from 27 entries under `skills/` to 85, and `loomground-solver/analyse-risks` installs its `scripts/run.py`, `references/eval.json`, `references/reference.md` and `agents/interface.yaml` beside its SKILL.md. All 26 skills re-vendored; `skills_lint` 13/26 → 26/26. `a2a-compliance/compliance-fleet` moves from `5c6f2c1` to `73439af`, where the source repository had already brought its 1081-character description under the 1024 limit — the vendored copy does not diverge from its source. `tests/test_skills_parity.py` now compares whole directories, and it, the catalogue and the release-register parity tests resolve their checkouts the way the vendoring script does and read the pinned commit rather than a checkout's working tree.
