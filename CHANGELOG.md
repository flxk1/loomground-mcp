# Changelog

## Unreleased

* Hosts: `hosts/` — how the server attaches to a host, with the artefacts. `hosts/README.md` gives the exact configuration per host (stdio for Claude Code and Codex, streamable HTTP with `--token` for n8n and Langdock) and states what has been executed and what has not: Codex ran it, the n8n community-node workflow ran it, the n8n built-in AI-Agent workflow imports but needs a model credential, the Claude Code run was never completed here, Langdock is documented only. `hosts/skill_to_platform.py` converts a SKILL.md into an n8n workflow or a Langdock assistant document (stdlib only; `--server-url` now defaults to `http://127.0.0.1:8765/mcp`). `hosts/n8n/` holds both proof workflows, credential ids replaced by placeholders. Three tests convert a vendored SKILL.md for each target; 99 tests.
* Auth: `serve --transport sse|streamable-http` takes `--token <str>` (or `LOOMGROUND_MCP_TOKEN`; the flag wins): with a token, every HTTP request to the MCP endpoints without `Authorization: Bearer <token>` (constant-time compare) is answered `401 {"error": "unauthorized"}`; an ASGI wrapper over the SDK's Starlette apps, run under uvicorn as before; stdio unaffected; without a token, behaviour is unchanged. Three transport tests (SSE via the flag, streamable-HTTP via the env, flag-over-env precedence); 96 tests.
* Tools: 1 new — `loomground_releases(repo=None)`, plane `loomground`: the family's release/pin register (`repos`: version, tag, commit, package, pypi per repository; `edges`: consumer, dependency, range, dev_pin, dev_pin_release, status per dependency; `accepted`, `skipped`, `generated`, `source`) from `RELEASES.json` vendored as `releases.json` (package data, byte-parity test against the loomground repository at 6acdf1f; CI fetches that commit once it is public, else the test skips); with `repo`, one record and the edges naming it; 41 tools.
* Pins: `requirements-dev.txt` moves to the release tags in the register where pip can resolve the set — loomground-factual 0.1.0, loomground-epistemic 0.1.0, oversight-certificate 0.2.0, enforcement-posture 0.5.1, effect-reconciliation 0.2.0, norm-freshness 0.3.0, obligation-discharge 0.1.0; `loomground-governance>=0.11,<0.12` is now declared (pinned at 0.11.0 before, unranged); the `loomground-deontic` range is lifted to `<0.3`. loomground-deontic (0.2.0), loomground-versum (0.13.0), loomground-solver (0.5.0), loomground-ingest (0.2.0) and loomground-norm (0.1.0) stay at their commits: at their release tags versum, solver and ingest declare `loomground-governance<0.9`, ingest and norm declare `loomground-solver<0.3`, and every available versum, solver, ingest and norm commit declares `loomground-deontic<0.2` — pip refuses the released set together, so those edges stay `unreleased-commit` until each releases with the lifted ranges.

* Skills over MCP: the family's 22 conformant SKILL.md files in public repositories as `skills/index.json` (repo, name, description, allowed_tools, commit, path, url), every body vendored at each repository's pushed main commit as package data; one MCP prompt per vendored body (`prompts/list` over stdio, SSE and streamable-HTTP; `prompts/get` = the body under `Skill <name> from <repo> @ <commit>; tools: …`; a shared name is qualified `<repo>/<name>`); 1 new tool `loomground_skill(name=None)`, plane `loomground` (the index, or one record with its body); parity test against every repository at its pin (CI fetches the public ones), catalogue–index consistency test; 40 tools.
* Tools: 1 new — `loomground_catalogue(query=None)`, plane `loomground`: the family map (`repos`, `pipeline`, `patch_from_documents`, `source`) from `CATALOGUE.json` vendored as `catalogue.json` (package data, byte-parity test against the loomground repository at 965198c); the server's instructions say to call it first; 39 tools.
* Tools: 4 new — the reader/writer languages: `factual_lower` (loomground-factual), `epistemic_extract` (loomground-epistemic), `norm_extract` (loomground-norm: rules lifted to deontic formulae), `topos_parse` (a statement-level reader for loomground-topos's `grammar/topos.ebnf`, implemented in `tools/topos.py`; every `.lt` block in the spec's examples parses); 38 tools.
* Tools: 13 new — deontic (`deontic_parse`, `deontic_conflicts`), versum write/curate (`versum_capture`, `versum_suggest`, `versum_confirm`, `versum_canon`), the seven loomground-solver skill scripts as tools (`solver_analyse_risks`, `solver_estimate_liability`, `solver_litigation_risk`, `solver_opponent_model`, `solver_probability`, `solver_strategy`, `solver_advise_addons`) with script-parity tests; 34 tools.
